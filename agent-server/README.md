# Agent server

Python service and CLI runners for repository analysis and evidence-grounded audits.

For code navigation, ownership and change-specific checks, see
[`docs/architecture.md`](docs/architecture.md). Fastify-facing routes and callback
payloads are summarized in [`docs/contracts.md`](docs/contracts.md).

## Backend agent discovery

The agent-server owns the discovery catalog. Backend clients can request:

```http
GET /api/agents/catalog
GET /api/agents/catalog/{agent_id}
```

The collection returns `schema_version: "1.0"`, `agents` and `workflows`. It describes
the direct agents (dummy and functional adequacy), project analysis stages,
maintainability manager/coordinators/investigators, security supervisor/components
and the deterministic report agent. Discovery does not instantiate agents or models,
access a repository, run an audit or check provider credentials.

Each entry includes:

- `agent_id`: canonical transport identity, and `aliases` for existing configuration names.
- `role`, `description`, `parent_ids`, `child_ids` and `workflow_ids`.
- `quality_attributes`: explicit quality contexts, independent of role and hierarchy.
  Maintainability participants declare `["maintainability"]`, security and its
  components `["security"]`, and the shared report agent both. Functional adequacy
  declares `["functional_adequacy"]`. Project architecture stages declare no quality
  attribute and identify their context through `workflow_ids: ["project-architecture"]`.
  Dummy/custom unclassified agents use an empty list. Context describes supported
  participation, not evidence that an agent ran or that DAST was performed.
- `execution_modes`: `direct`, `pipeline`, `audit`, `internal` or `snapshot`.
  Only `direct` entries can be sent to `POST /api/agents/run`.
- `requires_model` and `model_configuration_id`: the execution configuration key
  used by that participant. Security remediation shares `security`; the report
  agent and scanners need no separate model configuration.
- `availability`: `not_executed` for the DAST placeholder; it is not advertised as
  a working dynamic scanner.
- `detail_url`: detail with typed input/output schemas when available, and
  `configuration` generated by `describe_agent_config(...)` at **user** level.
  Internal runtime participants without standalone typed contracts have null schemas.

For example, a backend preparing `quality-audit` can:

1. Find the workflow by `workflow_id`.
2. Select `maintainability`, `security`, or both from `supported_attributes`.
3. Use `model_configuration_groups` to obtain the exact `stage_configs` keys for
   the selected attributes. All nine maintainability participants require entries
   when explicit configurations are supplied; security requires one `security` entry.
4. Use the matching `attribute_selections` entry to obtain the effective callback
   `stages` and complete `model_configuration_ids`. Security-only reports through
   `security`; maintainability and joint audits use `maintainability_manager`.
5. Submit the existing pipeline request to `run_url`.

`input_schema` on a workflow describes its existing execution input contract,
including developer operating overrides. It is **not** a settings-panel schema.
User panels must use the detail's `configuration.config_schema` and `defaults`;
those are derived from the owning configuration, exclude developer controls and
contain no credentials. Request overrides still undergo execution-time validation.

Example discovery in PowerShell:

```powershell
$catalog = Invoke-RestMethod "http://localhost:8000/api/agents/catalog"
$quality = $catalog.workflows | Where-Object workflow_id -eq "quality-audit"
$quality.model_configuration_groups.maintainability
Invoke-RestMethod "http://localhost:8000/api/agents/catalog/security"
```

Unknown canonical IDs/aliases return 404. The existing `GET /api/agents` and
`GET /api/agents/{agent_type}/schema` retain their direct-execution meaning.
The catalog does not make internal agents directly executable. Configuration and
maintainability hierarchy are derived from the existing registries, not backend lists.

## Configuration layout

- `config/agents/`: shared agent configuration contracts, budgets, provider policy and panel catalog.
- `src/server/agents/<agent_path>/config.py`: settings exclusive to an individual agent.
- `src/server/config/`: service infrastructure such as logging, tracing and environment loading.
- `config/dev-agents.yaml`: local model/service presets; excluded from distributions.

See [`config/agents/README.md`](config/agents/README.md) for configuration levels and examples,
and [`../docs/agent-server/`](../docs/agent-server/) for service/pipeline documentation.

The distribution includes both the `server` and `config` Python packages, including
agent-local prompts. Local YAML presets are retained in the checkout only.

```powershell
uv run project-architecture --help
uv run pytest src/test-agents tests --ignore=tests/test_functional_adequacy.py -q
```
## Unlimited cumulative token budgets

Cumulative token budgets are unlimited by default for all agents and audits.
This includes shared audit, personal agent, hierarchy and per-objective token
admission. Omitting `unlimited_token_budget`, or having no `launch.json`, retains
this default. Set `"unlimited_token_budget": false` in `agent-server/launch.json`
and restart agent-server to enable cumulative token caps for that process.

Actual usage and conservative estimates continue to be recorded. Context and
per-response output limits, model/tool call limits, provider rate quotas and
execution deadlines remain effective. Existing numeric token settings are retained
and take effect again when the flag is `false`. The file is resolved relative to
the server source location, independently of the current working directory.

Standalone `src/test-agents/run_*.py` runners also accept this flag alongside agent
limits in their `--config` JSON file. An explicit flag overrides the process launch
default for that run and its descendants; omitting it retains the launch default.
Other unknown agent configuration keys are still rejected before model creation.
