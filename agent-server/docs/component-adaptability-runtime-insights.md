# Component adaptability: runtime notes

- `maintainability/reusability/component_adaptability/` extends the established investigator
  interface, not a new framework. No reusability parent coordinator currently exists;
  public exports and the shared YAML/live harness provide the callable integration.
- Bounded index/lexical discovery prioritizes adaptation hypotheses, not defects.
  Python and JS/TS/TSX have structural indexes; other source has weaker file fallback.
  Imports are not a complete call graph or proof of mandatory dependency use.
- Inspection uses a structured `InspectionDecision`, never free-form readiness. Native
  conditional edges separate tools, validation, targeted reinvestigation, normal and
  limited exits. Invalid requests/corrections, limits and unverifiable blockers terminate.
- Verified obstacles need an explicit target, full component source, representative
  caller/configuration evidence and inspected seams/counterexamples. An unspecified
  target stays null; only explicitly assumed context-dependent risks are permitted.
  Existing injection/configuration can disprove a suspicion without forcing a finding.
- Root-key/context deduplication consolidates references while retaining original
  candidates and discarded/unknown hypotheses. Filter accepted findings and examine
  classifications/assumptions; completed does not mean globally portable.
- Existing compact/cache tools, provenance, retries, budgets and 14 RPM / 250,000 TPM
  apply. Smaller excerpts reduce context growth, but automatic transcript compaction
  is absent. Node durations, resource counters and content-free tool activity expose costs.
- Deterministic tests exercise actual graph/index/tool behavior with simulated model
  judgments; Google transport is mocked separately. `COMPONENT_ADAPTABILITY_LIVE=1`
  enables the optional paid seed evaluation. No offline test proves semantic accuracy.
  The agent README documents exact extension points, limits, commands and sample trace.
